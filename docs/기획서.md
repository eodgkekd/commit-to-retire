# 커밋에서 은퇴까지 — 기획서 v0.3

> 신입부터 은퇴까지, 한국 개발자의 커리어를 1년 단위로 살아보는 풍자 육성 게임.
> 서버 없이 브라우저에서 동작. 한 판 10~15분.

## 1. 확정된 방향

| 항목 | 결정 |
|---|---|
| 톤 | 현실 풍자 (야근, 레거시, 블라인드 드립) |
| 플레이 길이 | 10~15분 / 1턴 = 1년 / 약 25~35턴 |
| 고유명사 | 패러디 이름 (실명 사용 안 함) |
| 엔딩 평가 | 최고 직책·명성 + 업적 수집 |
| 제목 | **커밋에서 은퇴까지** |
| 캐릭터 그림 | 이모지·아이콘만 (재미가 검증되면 도트로 교체 검토) |
| 개인 생활 | 가볍게 — 이벤트 몇 개로만, 커리어 판단에 영향 주는 수준 |
| 연봉 표시 | 현실 숫자 (만 원 단위) |
| 확률 공개 | 숨김 — 결과를 보기 전까지 모름 |

연봉·자산은 평가 기준이 아니라 **보조 지표**(풍자 소재, 이직 판단용)로만 쓴다.

## 2. 핵심 루프 (1턴 = 1년)

```
[연초] 올해의 집중 선택 (1개)
   ↓
[연중] 자동 진행 → 능력치 성장, 프로젝트 성과 계산
   ↓
[이벤트] 랜덤 이벤트 1~2개, 각각 선택지 2~3개
   ↓
[연말] 인사고과(S/A/B/C/D) → 연봉 인상, 승진 심사
   ↓
[결과 화면] 수치 변화 + 커뮤니티 반응 피드
   ↓
[허브] 확인할 일: 이직 제안 / 승진 / 회사 소식 → 다음 해 or 은퇴
```

### 올해의 집중 (연초 선택)
| 선택 | 능력치 | 체력 | 그 밖에 |
|---|---|---|---|
| 업무에 올인 | 도메인 +5, 코딩 +2, 설계 +2, 평판 +1 | −15 | 고과 +15 |
| 기술 공부 | 코딩 +5, 설계 +5 | −8 | |
| 사이드 프로젝트 | 코딩 +3, 설계 +1, 평판 +4 | −12 | 고과 −5, 헤드헌터 확률↑ |
| 네트워킹·발표 | 소통 +5, 평판 +5 | −5 | 헤드헌터 확률↑ |
| 이직 준비 | 코딩 +1 | −5 | 고과 −10, 공고 3곳 지원·합격률↑, **승진 심사 제외** |
| 쉬어가기 | 없음 | +30 | 고과 −5, **승진 심사 제외** |

- 능력치는 주로 이 선택으로 자란다. 그냥 다니기만 해서 느는 양은 작다 (코딩 1.2 / 설계 0.7 / 소통 0.5 / 도메인 1.2 / 평판 0.1). 그래서 한 가지만 고르면 어느 직급에서 막힌다.
- 위 숫자에 회사 성장 배수·업종·학력·집중 육성(×1.3)이 곱해지고, 능력치가 높을수록 덜 자란다.
- 연초 화면은 선택지마다 올해 예상 체력 변화(회복 − 야근 − 집중)를 보여준다. 이벤트로 깎이는 양은 예상에 없다.
- 수치는 `src/data/career.ts`(집중)와 `src/data/balance.ts`(성장·체력·승진)에 있다.

## 3. 캐릭터 생성 (4단계)

### ① 기본 정보
- 이름, 아바타
- **시작 나이**: 22~32세. 늦게 시작하면 소통·도메인 보너스

### ② 학력
| 학력 | 특징 |
|---|---|
| 명문대 컴공 | 대기업·빅테크 서류 통과율↑, 시작 능력치 균형 |
| 지방대 컴공 | 기본형, 중견·중소 진입 쉬움 |
| 비전공 | 코딩↓, 도메인·소통↑ |
| 부트캠프 | 코딩 실전형, 설계↓, 스타트업 진입 쉬움 |
| 고졸 독학 | 시작 능력치↓, 성장률↑ (대기만성형) |
| 해외대 | 외국계 진입 쉬움, 연봉 협상 보너스 |

### ③ 주력 분야 (kickru처럼 합은 같고 분포만 다름)
백엔드 / 프론트엔드 / 모바일 / 데이터·AI / 인프라·DevOps / 게임 클라이언트

후보 3개를 보여주고 1개 선택 → "집중 육성 능력치" 2개 선택.

### ④ 첫 회사 + 업종
학력·능력치에 따라 **합격 가능한 회사만** 선택지로 나온다 (서류 탈락 연출도 재미 요소).

## 4. 능력치

| 능력치 | 의미 | 주로 쓰이는 곳 |
|---|---|---|
| 코딩 | 구현 속도·품질 | 고과, 장애 대응 |
| 설계 | 아키텍처, 큰 그림 | 시니어 이상 승진 조건 |
| 소통 | 회의, 설득, 문서 | 리드·매니저 트랙 |
| 도메인 | 업종 이해도 | 같은 업종에 오래 있을수록↑, 이직하면 일부 리셋 |
| 평판 | 업계 인지도 | 이직 제안, 디렉터·프린시펄 이상 승진 조건, 명성 점수 |
| 체력 | 0~100, 번아웃 게이지 | 0이 되면 번아웃: 그해 고과 D, 체력 50으로 복귀, 3회 누적이면 은퇴. 상단 카드에 "번아웃 n/3"으로 표시 |

- **평판은 실력이 있어야 오른다.** 코딩·설계·도메인 중 가장 높은 값이 40 이하면 평판 성장이 0.25배, 80 이상이면 1배, 그 사이는 비례한다. 실력 없이 발표만 다니면 평판이 느리게 오른다.
- 체력은 매년 20(40세부터 15) 회복하고, 회사 야근 강도(5/10/18/26)와 올해의 집중만큼 깎인다.
- **야근 경고** — '기술 공부'만 골라도 1년에 체력이 10 이상 깎이는 회사면 허브에 "야근이 버거운 회사예요" 카드가 뜬다. 몇 년 버틸 수 있는지와 야근 🔥가 적은 회사로 옮기라는 말을 보여 준다. 20대 기준 🔥4 회사(중소 SI·에이전시), 40세부터는 🔥3 회사도 걸린다 (`OVERWORK_WARNING`). 이 회사들에는 '다른 회사 친구들은 6시에 퇴근해요' 이벤트도 자주 나온다.

보조 지표: 연봉, 자산, 나이, 연차.

## 5. 회사

### 규모별 특성 (1.0 = 기준)
| 유형 | 연봉 | 성장 | 야근 | 위험 | 승진 속도 | 패러디 예시 |
|---|---|---|---|---|---|---|
| 대기업 본사 | 1.4 | 0.8 | 보통 | 매우 낮음 | 느림 | 삼선전자 |
| 대기업 SI 계열사 | 1.2 | 0.7 | 높음 | 낮음 | 느림 | 엘쥐씨엔에스 |
| 국내 빅테크 | 1.5 | 1.2 | 보통 | 낮음 | 보통 | 네모버, 까까오, 쿠팽, 토스트 |
| 외국계 | 1.6 | 1.0 | 낮음 | 중간(본사 감원) | 보통 | 구글리, 아마존강 |
| 중견 | 1.0 | 0.9 | 보통 | 낮음 | 보통 | — |
| 중소 SI·SM | 0.8 | 0.8 | 매우 높음 | 중간 | 빠름 | — |
| 외주 에이전시 | 0.8 | 1.1 | 매우 높음 | 높음 | 빠름 | — |
| 시드 스타트업 | 0.7 + 스톡옵션 | 1.4 | 높음 | 매우 높음 | 매우 빠름 | — |
| 시리즈B 스타트업 | 1.0 + 스톡옵션 | 1.2 | 높음 | 높음 | 빠름 | — |

**위험** = 연 단위로 폐업·구조조정·인수가 일어날 확률.

**히든 루트: 웰그램** — 캐릭터 이름을 `기룽이`로 지으면 첫 회사 화면에 🤫 웰그램이 나온다 (`hiddenFor`). 서류 없이 입사한다.
- 꿈은 크지만 망해 가는 스타트업: 초봉 2,600 + 스톡옵션, 성장 1.3, 야근 🔥4, 위험 0.4, 승진 매우 빠름
- 회사 사건이 나면 거의 폐업이지만 5% 확률로 엑싯하고, 엑싯하면 연봉 ×30
- 전용 이벤트 3개 (새벽 비전 공유, 월급 지연, N번째 피벗), 히든 업적 '기룽이의 웰그램'(달성 전에는 업적 목록에 안 보인다)
- 이직 시장(공고·헤드헌터)과 피드의 다른 회사 이름에는 나오지 않는다 (`publicCompanyTypes`)

회사 이름은 유형마다 10~12개 (`src/data/companies.ts`, 전체에서 겹치지 않게 `data.test.ts`가 검사). 다니다가 폐업한 회사는 연도별 기록에서 찾아 채용 공고와 헤드헌터 제안에 다시 나오지 않는다 (`closedCompanies`).

## 6. 직급과 진로

```
신입 → 주니어 → 미들 → 시니어 → 리드
                                   ├─ 매니저 트랙: EM → 디렉터 → VP → CTO
                                   ├─ IC 트랙: 스태프 → 프린시펄 → 펠로우
                                   └─ 이탈: 창업 / 프리랜서 / 강사·유튜버 / 공무원 / 치킨집
```

- 승진 조건 = 연차 + 능력치 기준 + 최근 고과 (회사 유형마다 기준이 다름)
  - 고과별 승진 확률 S 90% / A 70% / B 30%, 리드 위로는 자리가 적어 절반
  - **'쉬어가기'·'이직 준비'를 고른 해에는 승진 심사를 하지 않는다.** 쉬기만 해서는 직급이 오르지 않는다
  - 허브의 **다음 승진 조건 카드**가 다음 직급에 필요한 경력 연차와 능력치를 지금 값과 나란히 보여준다. 리드에서 트랙을 고르기 전에는 두 트랙의 조건을 모두 보여준다
  - 정확한 직급별 기준은 `src/data/career.ts`
- 연봉 상한: 시장 연봉(회사·업종·직급·연차 기준)의 1.3배를 넘으면 인상 폭이 30%로 줄고, 이직 제안은 시장 연봉의 1.5배를 넘지 않는다
- 리드에서 트랙을 고른다 (전환점 이벤트)
- 창업은 사이드 프로젝트 플래그가 있으면 열리고, 이후 매년 생존 판정

### 이직 시장 (`src/engine/jobs.ts`)
가만히 있으면 제안이 거의 오지 않는다. 옮기려면 직접 지원해야 한다.

**헤드헌터 제안 (수동)** — 연말에 확률로 1건. 이미 합격한 제안이라 바로 수락할 수 있다.
- 기본 확률: 1~2년차 3% / 3~10년차 12% / 11~20년차 15% / 그 뒤 8%
- 보정: 평판 1당 +0.3%p, 네트워킹·이직 준비 집중, S 고과 +5%p, 50세 이후 절반 (최대 60%)

**채용 공고 + 지원 (능동)** — 연말 허브에 공고 5개.
- 지원 가능 수: 평소 1곳 / 연초에 '이직 준비'를 골랐으면 3곳 / 실직 상태 5곳
- 전형: 서류 → 코딩테스트 → 기술 면접 → 임원 면접, 단계마다 숨은 통과 확률 (5~95%)
  - 서류: 서류 점수 vs 회사 문턱 + 경력 기대치(연차×2.5, 최대 40)
  - 코딩테스트: 코딩 / 기술 면접: (코딩+설계)÷2와 연차 기대치 / 임원 면접: 소통
  - '이직 준비' 집중이면 단계마다 +10%p, 승진 포지션 공고는 기준이 높다
- 결과는 한 단계씩 연출해서 보여준다. 합격하면 받은 제안에 추가
- 승진 포지션 공고: 한 단계 위 직급. 그 직급의 최소 연차·능력치를 채우고 현 직급 2년 이상일 때만 가끔 뜬다

**실직 후 전부 탈락** — '취업 준비하며 1년 보내기'. 연봉 없이 생활비 2,400만이 자산에서 빠지고, 경력 연차는 늘지 않는다. 다음 해에 다시 5곳 지원.
- 실직 중에는 같은 직급 공고만 나온다 (잘리고 승진해서 재취업하는 일은 없다)

### 40대 이후: 권고사직과 치킨집
60세 정년까지 한 회사에서 일하는 건 비현실적이라, 40대부터는 회사에서 밀려나고 다시 들어가기도 어렵게 만든다. 수치는 `src/data/balance.ts`.

**권고사직** — 회사 사건(폐업·구조조정)과 별개로 매년 굴린다 (`AGE_LAYOFF_CHANCE`).
- 40~44세 3% / 45~49세 7% / 50~54세 12% / 55세 이상 18%. 금융권·공공 IT는 정년이 보장돼서 0.3배
- 40대 이후 이벤트에도 회사를 떠나는 선택지가 많다 (`effects.jobLoss`): 희망퇴직 공고, 책상이 옮겨졌어요, 인사팀 면담, "그 연봉이면 주니어 두 명", 임원 계약 미연장, AI 전환 구조조정, 임금피크제(55세 이상 대기업·금융). 대부분 위로금을 준다
- jobLoss가 생긴 해는 연봉 인상과 승진이 없고, 연말에 실직 상태로 허브에 간다

**재취업 난이도**
- 40세부터 서류·기술 면접·임원 면접 통과 확률이 1년에 2%p씩 깎인다 (최대 35%p, 코딩테스트는 그대로) (`AGE_HIRING_PENALTY`)
- 취업 준비로 보낸 해가 이어질수록 서류에서 1년마다 15%p (`GAP_HIRING_PENALTY`). 공백기는 '이직 준비'로 기록돼 +10%p를 받으므로 첫해는 거의 상쇄되고 둘째 해부터 아프다

**치킨집 창업** — 실직한 40세 이상은 허브에서 재취업 대신 치킨집을 차리고 은퇴할 수 있다 (한 번 더 확인한다). 수치는 `CHICKEN`
- 창업비 1억이 자산에서 빠진다
- 결과: 프랜차이즈 대박 12% / 동네 맛집 38% / 폐업 50%. 소통 50을 기준으로 1점마다 대박 +0.3%p, 폐업 −0.5%p
- 동네 맛집은 정년까지 해마다 3,000만, 프랜차이즈는 6억을 번다. 폐업은 창업비만 날린다
- 업적: 개발자의 종착역(치킨집을 차림) / 치킨 프랜차이즈 대표(대박)
- 엔딩 화면 첫 줄이 결과에 따라 바뀐다 ("퇴직금으로 차린 치킨집이 전국 프랜차이즈가 됐어요" 등)

봇 기준 평균 이직: 업무 올인 6.3회 / 무작위 10.2회 / 이직러 13.6회 (33년 기준). 40대 이후 권고사직이 생기면서 크게 늘었다

### 개인 생활 (가볍게)
별도 시스템 없이 이벤트 몇 개 + 플래그로만 처리한다.

| 이벤트 | 결과 플래그 | 커리어에 미치는 영향 |
|---|---|---|
| 결혼 | `married` | 자산↓, 체력 회복량↑, 고위험 선택(창업·스타트업 이직) 망설임 이벤트 |
| 출산 | `hasChild` | 육아휴직 선택지 — 회사 유형별 눈치 정도가 다름 |
| 주택 대출 | `mortgage` | 몇 년간 연봉 하락 이직·창업 선택 시 경고 |
| 부모님 병환 | — | 1년간 체력↓, 휴직 선택지 |

### 확률 숨김 원칙
- 선택지 결과 확률은 화면에 표시하지 않는다
- **모든 선택지는 언제나 고를 수 있다.** 능력치로 선택지를 막지 않는다
- 대신 선택지에 숨은 능력치 판정(`check`)이 있다. 능력치가 기준보다 낮으면 실패 확률이 오르고 높으면 내려간다 (기준의 절반 ×3, 기준과 같으면 ×1, 1.5배 ×0.5)
- 결과 화면에서 운인지 실력인지 슬쩍 드러낸다: "운이 좋았어요" / "실력으로 해냈어요"
- **확률은 숨기지만 결과 수치는 보여준다.** 결과 문구 아래에 실제로 바뀐 값이 칩으로 나온다 (체력 −20, 코딩 +2, 고과 점수 +8, 연봉 +10%, 업적 등). 무엇이 얼마나 바뀌는지 알아야 다음에 다르게 고를 수 있다

### 같은 이벤트가 반복되지 않게
이벤트 수가 한 판에 뽑는 횟수(약 49회)보다 적어서 그대로 두면 같은 이벤트를 여러 번 본다. 세 가지로 막는다.

**쿨다운** — 한 번 나온 이벤트는 3년 동안 다시 나오지 않는다 (`EVENT_COOLDOWN_YEARS`). 이미 여러 번 본 이벤트는 가중치가 `1 / (1 + 본 횟수)`로 줄어든다. 후보가 전부 최근에 본 것이면 가장 오래전에 본 이벤트부터 다시 나온다.

**심각도** — `severity: true`인 이벤트는 뽑힐 때 1(가벼운 일)·2(보통 일)·3(큰일)을 35 / 45 / 20 비율로 굴린다.
- 결과의 체력·고과·능력치 변화에 ×0.6 / ×1 / ×1.5 (0이 아니던 값이 0이 되지는 않는다). 연봉·자산·업적은 그대로
- 실패 결과가 나올 확률에 ×0.8 / ×1 / ×1.3
- 이벤트 화면에 심각도 배지를 보여준다. 확률이 아니라 "일이 얼마나 큰가"라서 숨기지 않는다

**변수와 변형** — 뽑힐 때 한 번 굴려 `pendingEvents`에 저장한다. 저장된 값만 읽으므로 이어하기를 해도 같은 장면이 나온다.
- `vars`: 문구에 `{이름}`으로 들어가는 값. 목록에서 고르거나 정수 범위에서 굴린다. `bySeverity`로 심각도별 후보를 따로 둘 수 있다 (가벼우면 "오타 수정", 크면 "결제 모듈 교체")
- `{name}` `{company}` `{rank}`는 언제나 쓸 수 있다
- 조사는 `{who}(이)가`, `{change}(을)를`, `{channel}(으)로`처럼 쓰면 받침에 맞게 바뀐다 (`src/engine/text.ts`, 피드와 같은 도우미)
- `variants`: 같은 선택지를 쓰는 다른 장면(제목·본문). 조건을 붙일 수 있다. 결과 문구와 어긋나지 않게 쓴다
- 소주 세례(일부러 그대로 둠)를 뺀 모든 이벤트에 변수나 변형이 붙어 있다. 새 이벤트도 되도록 붙인다
- 변수 이름은 영문자와 `_`만 쓴다 (숫자를 넣으면 치환되지 않는다)

### 시대 흐름
게임 내 연도가 지날수록 **AI 자동화 압력**이 커진다. 주니어 채용 감소, 단순 코딩 가치 하락, 설계·도메인 가치 상승. 후반부 전략이 달라지게 만드는 장치.

### 데이터 형식 (콘텐츠는 이 형식으로 계속 추가)
실제 파일은 `src/data/events.ts`의 타입 붙은 배열이다 (`GameEvent`, 정의는 `src/engine/types.ts`).
```ts

  category: '장애',
  emoji: '🚨',
```

## 9. 엔딩과 평가

### 은퇴 조건
- 60세 도달 / 자진 은퇴 / 번아웃 3회 누적 / 창업 실패 후 재기 포기 / 실직 후 치킨집 창업 (40세 이상, 6장)

### 명성 점수 = 최고 직책 점수 + 평판×0.25 + 업적 점수
등급 기준: S 125 / A 112 / B 85 / C 50 이상 / 그 아래 D

평판은 승진 조건에도 들어가므로 명성 점수에서는 비중을 낮게 둔다 (`FAME_REPUTATION_WEIGHT`).

**분포 (`npm run balance`)** — 40대 이후 권고사직·재취업 난이도가 들어가면서 S·A가 크게 줄었다 (예전 승진 조건 봇 매니저 S 25%)

| 플레이 방식 | S | A | B | C | D |
|---|---|---|---|---|---|
| 무작위 봇 | 0% | 1% | 14% | 77% | 9% |
| 승진 조건을 보고 고르는 봇 (매니저) | 3% | 10% | 38% | 47% | 3% |
| 승진 조건을 보고 고르는 봇 (IC) | 5% | 17% | 47% | 29% | 3% |
| 매년 네트워킹만 (매니저) | 0% | 1% | 25% | 49% | 25% |
| 매년 업무에 올인만 (IC) | 0% | 0% | 13% | 72% | 16% |
| 매년 쉬어가기만 | 0% | 0% | 0% | 1% | 99% |

**필승법 검사** — `npm run balance`는 매년 같은 집중만 고르는 봇(집중 6종 × 트랙)을 400판씩 돌린다.
- 어느 하나라도 S가 20%를 넘으면 실패한다.
- 승진 조건을 보고 섞어 쓰는 봇의 평균 명성이 모든 고정 전략보다 높지 않으면 실패한다.
- 봇은 예상 체력이 25 아래로 떨어질 해에는 쉰다 (연초 화면의 예상 체력을 보고 판단하는 사람과 같은 기준).
| 등급 | 칭호 예시 |
|---|---|
| S | 한국 IT의 전설 |
| A | 업계가 아는 이름 |
| B | 믿고 맡기는 시니어 |
| C | 무난한 월급쟁이 |
| D | 치킨집 사장님 |
